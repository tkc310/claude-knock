# 0009 公式告示より先の年も、暦法で計算して出す

- 日付: 2026-10-21
- 状態: 採用

## 背景

ADR-0008 の「決めたこと」1 で、core の `supportedRange` を「暦法を確かめた範囲」とし、公式告示で確かめた 2027 年の末までにした。範囲の外は RangeError になる。

トップページは今年と来年の行事を出す。このため、2027-01-01 以降にビルドすると 2028 年分が範囲の外になり、ビルドが失敗する。2028 年分の告示は、例年どおりなら 2027 年の秋まで出ない。

暦法で計算できないから止めていたのではない。年表は基準日から 100 年分（仏暦 2567〜2666 年）できていて、公式の日付 17 件は上書きなしで一致した。止めていたのは、公式の日付で確かめていない年を出さないためである。

## 決定

**`supportedRange` を年表の全体にする。公式告示より先の年も、暦法で計算した日付を出す。**

- 範囲の外が RangeError になるのは変えない。範囲の意味を「暦法を確かめた範囲」から「年表の範囲」に変える
- 表示の範囲（今年と来年）は、これまでどおり呼び出し側（`src/pages/`）が決める（ADR-0008 の 1）
- 翌年分の告示が出たら `tests/fixtures/` に足す。暦法と食い違えば上書きのテスト（`tests/core/overrides.test.ts`）が落ちるので、そのとき `YEAR_KIND_OVERRIDES` で年型を直す

## 理由

- ワンプラ・オークパンサー・トートカティンには、もともと公式の日付が無い。今も暦法だけで出している。ブーチャー 3 行事の告示より先の年だけを止める理由は弱い
- タイで配られる暦も、計算か公式かを分けて示さない（ADR-0008 の 2）
- 食い違いの見つけ方は、ADR-0008 の上書きのテストがそのまま担う。範囲を広げても、確かめる仕組みは変わらない
- 範囲を告示に合わせて止めると、毎年の告示が出るまでビルドが失敗する。告示の出る時期に開発が縛られる

## 影響・トレードオフ

- 告示が出ていない年のブーチャー 3 行事は、暦法と食い違えば誤った日付を出す。告示が出て fixtures に足すまで、誤りには気づけない
- 暦法の分岐のうち、公式の日付で通っていないもの（閏月の候補が 2 年続く年、閏月と閏日が重なる年）は、確かめないまま使う。過去の告示で確かめる作業はバックログに残す（ADR-0008 の 3）
- 年表の終わり（仏暦 2666 年）より先は、RangeError のまま残る
- 年表より前の公式の日付で照らすと、暦法は仏暦 2557・2559 年の年型を外していた（閏日を 2 年早く置く）。年表の範囲に同じ条件の年は無いが、暦法が常に当たるわけではない（`YEAR_KIND_OVERRIDES`、`tests/core/year-kind.test.ts`）
