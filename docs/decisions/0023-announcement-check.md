# 0023 タイ中央銀行の API で告示を毎月照合し、知らせることがあれば Issue を立てる

- 日付: 2026-10-22
- 状態: 採用（ADR-0015 の「告示の照合は 12 月の手作業」を自動にする）

## 背景

ADR-0009 で、公式告示より先の年も暦法で計算して出すことにした。告示が暦法と食い違っても、誰かが告示を正解データ（`tests/fixtures/official-dates.json`）に足すまで気づけない。これまでは毎年 12 月に人が `check-announcements` スキルで確かめていた。利用者から、API やスクレイピングで自動化できないか、タイ中央銀行以外の手段も含めて検討するよう求められた。

## 調べた情報源

| 情報源                                 | 公式 | 機械で読めるか       | 結論                     |
| -------------------------------------- | ---- | -------------------- | ------------------------ |
| タイ中央銀行の API（金融機関の休日）   | ◎    | ◎ JSON               | 採用                     |
| タイ中央銀行の休日のページ・告示の PDF | ◎    | △・×                 | 壊れやすい               |
| 内閣の決定（thaigov.go.th）            | ◎    | × 形式が年ごとに違う | 不採用                   |
| 在外公館の休日表（外務省の PDF）       | ○    | ×                    | 人が補助に使う           |
| 仏教庁・宗教局                         | ◎    | × 自動の取得を拒否   | 不採用                   |
| Google カレンダーなどの祝日の ICS      | ×    | ◎                    | 出典にできないので不採用 |

## 決定

- タイ中央銀行の API（`GET https://gateway.api.bot.or.th/financial-institutions-holidays/?year=YYYY`、ヘッダー `Authorization` に API キー）から、今年と来年の休日を取る
- 英語の行事名から、マーカ・ウィサーカ・アーサーラハのブーチャーとカオパンサー（休日の年）を当てる。振替休日は外す
- 暦の計算（`occurrences`）と正解データに照らし、`ok`・`none`（告示がまだ無い）・`new`（正解データに無い公式の日付）・`mismatch`（計算と食い違い）にまとめる（`scripts/announcements/check-bot.ts`、`make announcements`）
- `.github/workflows/announcements.yml` を毎月 2 日に動かし、`new`・`mismatch`・今年の `none` のときに Issue を立てる（同じ題の Issue が開いていればコメントを足す）。来年分の `none` は、例年 8 月ごろまでの普通の状態なので知らせない
- 正解データへの追加は自動にしない。出典（告示の PDF）を人かスキルで確かめてから足す
- API キーは secrets の `BOT_API_TOKEN`。Keepalive が Announcements も有効にし直す（ADR-0022）

## 理由

- 行事の日付はすべて同じ年表（年型の並び）から計算するので、休日になる 3 つのブーチャーが合えば、その年のほかの行事も正しいと言える
- 食い違いは年型の上書きという判断が要るので、自動で直さず人に知らせる
- GitHub Actions は公開リポジトリなら無料で、Claude の定期タスクの費用がかからない

## 影響・トレードオフ

- 休日ではない行事（アッタミー・ブーチャー、オークパンサー、ロイクラトン）は API に載らない。年型が正しければ計算で合う
- API キーには期限や仕様の変更があり得る。取れなくなると今年の `none` として Issue が立つ
