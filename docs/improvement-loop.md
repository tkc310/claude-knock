# 改善ループ

このカレンダーは「使う → 気づく → 記録する → 直す → 再発を防ぐ → 振り返る」を回して育てます。
人が回しても、AI エージェントが回しても同じ手順になるよう、段階ごとに置き場所と道具を決めています。

```
   ┌──────────── 使う（make dev の画面・ICS の取り込み）
   │                    │ 気づく
   │                    ▼
   │   ┌─ 自動: make check / make test / make build ─┐   ┌─ 手動: 会話・メモ ─┐
   │   └──────────────────────┬──────────────────────┘   └─────────┬─────────┘
   │                          ▼                                    ▼
   │                docs/improvement/backlog.md（改善候補）
   │                          │ 直す（1 コミット 1 改善）
   │                          ▼
   │   再発防止: 正解データ / テスト / 型 / lint ルール / ルール文書 / ADR / 手順
   │                          │
   └──── docs/improvement/log.md に記録 ◀┘
```

## 1. 気づく

### 自動

CI はまだありません。どれも手元で、コミットの前に実行します。

| 仕組み       | 何を見つけるか                                                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `make check` | `vp check` がフォーマット（oxfmt）と lint（oxlint。型を使う規則と tsgolint の型検査を含む）を見る。続けて `astro check` が `.astro` を含めて型を見る |
| `make test`  | Vitest。`tests/data.test.ts` が行事名の 3 表記と `id` の重複を、`tests/fixtures.test.ts` が正解データの出典 URL（https）と `eventId` を検査する      |
| `make build` | `dist/` への静的ビルド。`.astro` から React の部品に渡す値の誤りなど、ビルドしないと出ない失敗                                                       |

### 手動

画面やカレンダーアプリで使っていて気づいたことは、エージェントとの会話で伝えるか、自分でメモします。
どちらも最後は `docs/improvement/backlog.md` に 1 行で残します。

## 2. 記録する

改善候補は [`improvement/backlog.md`](./improvement/backlog.md) にまとめます。優先度は次の順で判断します。

1. 日付の誤り（暦計算・正解データの誤り）。利用者が誤った日に寺へ行くことになる
2. ドメインルールの破れ（[`CLAUDE.md`](../CLAUDE.md)。3 表記の併記、出典 URL 必須、太陰暦は計算する、原始仏教の行事に限る）
3. 表示と ICS 配信の品質（読みやすさ、アクセシビリティ、カレンダーアプリでの取り込み）
4. 開発体験（コマンド、検査、ドキュメント、エージェントの手順）
5. 見た目の好み

## 3. 直す

- 1 コミット 1 改善。大きいものは分割し、残りをバックログに戻す
- 実装より先にテストを書く。日付を扱うなら、先に `tests/fixtures/` に公式の日付と出典を置く
- 値や方針を変えたら ADR を足す（[`decisions/`](./decisions/README.md)）
- `src/components/ui/`・`src/lib/`・`src/styles/8341-ui.css` は直接編集しない。更新は `make ui-add`

## 4. 再発を防ぐ（いちばん大事）

**直しただけで終わらせない。** 同じ種類の問題が二度と起きないよう、次のどれかを必ず足します。

| 問題の種類                      | 足すもの                                                                                |
| ------------------------------- | --------------------------------------------------------------------------------------- |
| 日付の誤り                      | 公式の出典 URL を付けた正解データを `tests/fixtures/` に置き、`tests/` にテストを足す   |
| 行事名・表記のずれ              | `tests/data.test.ts` の検査に足すか、`src/data/events.ts` の `EventDefinition` 型で表す |
| 行事ごとの項目の足し忘れ        | 対応表を `Record<EventId, …>` にして、足し忘れを型検査で見つける                        |
| lint で見つけられる書き方の問題 | `vite.config.ts` の `lint` に規則を足す                                                 |
| 8341-ui の使い方の誤り          | `AGENTS.md` に追記する（例: Astro の要素は props でなく slot で渡す）                   |
| 判断基準のあいまいさ            | `CLAUDE.md`・`AGENTS.md` に追記するか、ADR を足す                                       |
| 手順の抜け・やり直し            | `Makefile` のコマンドか `.claude/skills/` のスキルに手順を足す                          |

`CLAUDE.md` は利用者が書いた指示書です。エージェントは黙って書き換えず、変更案を示して利用者に確認します。

どうしても仕組みにできないときは、`log.md` の「再発防止」に「—」と書き、理由をバックログに残します。

## 5. 振り返る

[`improvement/log.md`](./improvement/log.md) に 1 改善 1 行で記録します（新しいものを上に）。
ときどきログを見返し、同じ種類の改善が続いていれば、ルール文書や検査の仕組みそのものを見直します。見直した結果は ADR に残します。

## AI エージェントが回す場合

手順は [`.claude/skills/improve/SKILL.md`](../.claude/skills/improve/SKILL.md) にまとめています。エージェントは次の順で動きます。

1. `docs/improvement/backlog.md` を読み、優先度の高いものを 1 つ選ぶ（頼まれたものがあればそれ）
2. `CLAUDE.md` と関連する ADR を読んでから直す
3. 上の「再発を防ぐ」に従ってテストや検査を足す
4. `make check`・`make test`・`make build` が通ることを確かめ、`log.md` に 1 行足し、バックログから消す

会話で指摘を受けて直したときも同じです。指摘の内容は `log.md` に残し、同じ指摘を二度受けないよう再発防止を足します。
