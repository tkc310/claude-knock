# AI エージェントと開発する

このカレンダーは AI エージェント（Claude Code など）と一緒に開発します。このページは、エージェントが何を読み、どう動くかをまとめたものです。

## エージェントが読むファイル

| ファイル                                | 役割                                                                             |
| --------------------------------------- | -------------------------------------------------------------------------------- |
| `CLAUDE.md`                             | 利用者が書いたドメインルールと作業ルール。エージェントは書き換えず、変更案を示す |
| `AGENTS.md`                             | どのエージェントにも共通の作業ガイド（コマンド・まず読むもの・守ること）         |
| `docs/improvement/backlog.md`・`log.md` | 改善候補と、直したことの記録                                                     |
| `docs/decisions/`                       | 判断の理由（ADR）                                                                |
| `.claude/skills/improve/SKILL.md`       | 改善を 1 件回す手順                                                              |

## スキル

| スキル    | 使うとき                                                |
| --------- | ------------------------------------------------------- |
| `improve` | 改善を 1 件回す（バックログから選ぶ・会話の指摘を直す） |

## サブエージェント

| サブエージェント           | 使うとき                                                                        |
| -------------------------- | ------------------------------------------------------------------------------- |
| `thai-calendar-researcher` | 行事 1 件の日付の規則と由来を一次情報から調べ、`docs/events/<id>.md` にまとめる |

## エージェントに任せるときの進め方

1. **頼む**: 直したいこと、または「バックログから 1 件」と伝える。大きな変更はプランモードで計画を書かせてレビューする
2. **直させる**: エージェントは `improve` スキルに沿って、`CLAUDE.md` と関連する ADR を読んでから直す。日付を扱うなら、先に `tests/fixtures/` に公式の日付と出典を置かせる
3. **再発を防がせる**: 直しただけで終わらせず、テスト・検査・ルール・スキルのどれかを足させる（[改善ループ](./improvement-loop.md) の「再発を防ぐ」）
4. **記録させる**: `docs/improvement/log.md` に 1 行、方針を変えたら ADR を 1 つ
5. **確かめる**: `make check`・`make test`・`make build` が通ることを見る。画面を変えたら `make dev` で見る

## 指摘の伝え方

会話で指摘するときは、「何がどう困るか」を書くと再発防止まで届きやすくなります（例:「この行事の日付が公式発表と 1 日ずれている。表示の日に寺へ行っても行事が無い」）。
エージェントは指摘を `log.md` に残し、同じ種類の指摘が続いたらルール文書か検査に格上げします。
